# Policy Impact Simulator

A full-stack decision-support prototype for exploring how proposed urban transport policies may affect traffic, environmental indicators, and socio-economic outcomes. The application compares a baseline scenario with a selected policy scenario and presents the result through a React dashboard.

> **Project status:** Research / academic prototype. The simulation uses local traffic data and model/heuristic estimates; its outputs are not calibrated engineering forecasts and should not be used as the sole basis for real infrastructure decisions.

## What the application does

- Accepts a location, policy type, and scenario parameters.
- Models five policy types: tunnel, flyover, road widening, signal optimisation, and metro extension.
- Predicts baseline and modified traffic travel-time indicators using a trained Random Forest regression model.
- Applies policy-specific scenario transformations before predicting the modified scenario.
- Computes derived traffic, environmental, and economic indicators.
- Uses an evidence subsystem to retrieve and validate supporting material for a scenario.
- Generates a deterministic, template-driven planner summary with traceable input values.
- Displays results, comparisons, history, feature importance, and report-oriented views in the frontend.

## Architecture

```text
React dashboard
   └── Flask API (/api/*)
         ├── Traffic model and feature preparation
         ├── Policy scenario engines
         ├── Environmental calculations
         ├── Socio-economic calculations
         ├── Evidence retrieval / validation
         ├── Deterministic planner summary
         └── MongoDB history and traffic data
```

The main simulation entry point is `backend/app/routes/simulation.py`; policy transformations are orchestrated by `backend/app/simulation/scenario_engine.py`. The planner narrative is generated by `planner_engine.py`, not by a free-form LLM call.

## Repository layout

- `backend/app/routes/` — simulation, comparison, history, traffic, visualization, and feature-importance routes.
- `backend/app/ml/` — model wrappers, training, and evaluation helpers.
- `backend/app/simulation/` — policy, environmental, socio-economic, evidence, and planner engines.
- `backend/app/evidence/` — evidence query, search, scoring, and validation.
- `backend/data/` — local data and evidence assets.
- `frontend/src/` — dashboard, simulator, workspaces, charts, and reports.
- `scripts/` — data preparation and model-training utilities.

## Run locally

### Option A: Docker Compose

From the repository root:

```bash
docker-compose up --build
```

Check the Compose file for the configured service ports and database settings.

### Option B: Separate services

Backend:

```bash
cd backend
python -m venv .venv
# Activate the virtual environment, then:
pip install -r requirements.txt
python run.py
```

The Flask development entry point listens on port `5001`.

Frontend:

```bash
cd frontend
npm install
npm start
```

The frontend development server is configured for port `3000` and proxies API requests to the backend.

Configure MongoDB and any required local model/data artifacts before running the complete workflow. Refer to the scripts under `backend/scripts` for data seeding and model training.

## Core API

The primary endpoint is `POST /api/simulate`. Additional route modules cover comparisons, history, traffic data, visualization, and feature importance. See `backend/app/routes/` for the implemented route definitions.

## Current limitations

- Some traffic inputs and training data are synthetic or locally prepared; results do not represent a validated real-world traffic model.
- Environmental, noise, fuel, ROI, and socio-economic outputs include formula-based estimates and assumptions.
- Evidence availability depends on the local evidence store and the configured data.
- The checked-in test modules are currently empty; do not treat the presence of a `tests/` directory as evidence of an automated passing suite.
- The repository README previously described only a narrower Random Forest / planner flow; the current code also includes policy engines, evidence handling, history, and report views.
